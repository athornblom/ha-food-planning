# Food Planning for Home Assistant

A custom integration that keeps a recipe list and a food shopping list in
Home Assistant. Paste a link to a recipe page or a TikTok video and the
recipe is extracted by an AI model and saved; one button adds its
ingredients to the shopping list.

Extraction goes through Home Assistant's own **AI task** feature, so the
API key and model live in an AI integration you already trust (for example
Anthropic with Claude Haiku 5.5), not in this integration.

> [!WARNING]
> This is a personal hobby project, provided as is, without warranty of
> any kind. Use it at your own risk. It sends recipe pages and your food
> lists to the AI provider you configure, and that provider bills you for
> the API usage. Keep backups of your Home Assistant configuration.

## Installation

[![Open in the Marketplace](https://my.home-assistant.io/badges/marketplace_repository.svg)](https://my.home-assistant.io/redirect/marketplace_repository/?owner=athornblom&repository=ha-food-planning&category=integration)

1. Click the button above, or go to Settings → Marketplace → ⋮ → Custom
   repositories and add this repository as an **Integration**.
2. Install **Food Planning** and restart Home Assistant.
3. Add the integration:

   [![Add integration](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=food_planning)

   or Settings → Devices & services → Add integration → **Food Planning**.

Updates show up in the Marketplace when a new GitHub release is published.

### Requirements

- Home Assistant 2026.11 or newer.
- An AI integration that provides an AI task entity, e.g. **Anthropic**
  (Settings → Devices & services → Add integration → Anthropic) with a
  model such as Claude Haiku 5.5. API usage is billed by the provider; a
  Claude subscription does not include API usage.

## How a link becomes a recipe

1. **Recipe pages:** most recipe sites embed the recipe as schema.org
   structured data. If it's there, only that is sent to the model, which
   keeps imports small and accurate. Otherwise the page's visible text is
   sent.
2. **TikTok:** the video's caption is read from the data TikTok embeds in
   the public video page (with TikTok's oEmbed endpoint as a fallback). Videos where the recipe is only spoken, with nothing written
   in the caption, can't be imported yet.
3. **Sites that block automated access** (some large recipe sites do) are
   respected rather than worked around: the import fails with a message
   saying so. Copy the recipe text and paste it into the recipe card
   instead.
4. The AI task returns a structured recipe (title, servings, ingredients,
   steps, notes), written in the configured language and with US units
   converted to metric.

## What you get

### Ready-made dashboard

The integration ships a whole dashboard with three views, **Inköpslista**,
**Hemma** and **Recept**, switched with tabs at the top. The views are
subviews, so the back arrow returns to wherever you opened the dashboard
from (set `back_path: /lovelace/0` in the strategy to always go to a
specific view). It's generated by the integration, so it follows its
updates.

1. Settings → Dashboards → Add dashboard → *New dashboard from scratch*,
   give it a name (e.g. "Mat").
2. Open it, ⋮ → Edit dashboard → ⋮ → Raw configuration editor, and replace
   everything with:

   ```yaml
   strategy:
     type: custom:food-planning
     # language: sv          # sv (default) or en
     # back_path: /lovelace  # optional: where the back arrow goes
   ```

To rearrange it yourself, use ⋮ → **Take control**: it becomes an ordinary
dashboard you can edit, but stops following the integration's updates.

### Cards

The dashboard is built from three cards, also usable on their own:

- `custom:food-planning-list-card` with `list: shopping` or `list: pantry`:
  add, tick off, tap to edit, ✕ to delete. Sections are named for what
  they are ("Att köpa" / "I korgen", "Finns hemma" / "Slut"). The shopping
  list has **Flytta till Hemma** and **Rensa korgen**.
- `custom:food-planning-cook-card` (on the Hemma view): which recipes can
  be cooked with what's at home, and which are close (missing at most
  `almost: 2` ingredients) with a **+ Handla** button for what's missing.
- `custom:food-planning-nav`: the tabs between the views.
- `custom:food-planning-card`: the recipes.

The recipe card:

```yaml
type: custom:food-planning-card
# title: Recept      # optional
# language: sv       # sv (default) or en
```

- A field at the top takes a **link** (recipe page or TikTok) or pasted
  **recipe text**, for sites that block automated access.
- Recipes show as a grid of images. Tap one for the full recipe: image,
  ingredients (tap to tick off while cooking), numbered steps, tips, a link
  to the source, and buttons to add the ingredients to the shopping list or
  delete the recipe (asks for confirmation).
- The ✎ button edits a recipe: name, servings, ingredients and steps (one
  per line), tips and source link.
- **Categories** (Middag, Efterrätt, Bakning, …) show as colored labels,
  with an icon for the common ones (🍰 Efterrätt, 🍽️ Middag, …). The AI
  picks fitting ones from your list when importing; change a recipe's with
  ✎, and filter by category in the card. **✎ Kategorier** in the card
  edits the list itself: rename (recipes keep the category), remove, add,
  and describe what belongs in each ("dips, tapas, chips and other food
  to share"). The AI goes by these descriptions; the default categories
  come with one.
  **Save and re-sort all recipes** then has the AI pick categories again
  for every recipe, in one call per 25 recipes. The list is also on the
  settings page (Configure), one per line.
- **What's at home decides "ready to cook".** Every ingredient and At home
  item gets a short product name ("2 finhackade schalottenlökar" →
  "schalottenlök", "Parmesan, bit" → "parmesan"), and an ingredient is at
  home when an At home item has the same name. The check is instant and
  local; the AI is only asked to name texts it hasn't seen before (a new
  recipe, a new item), and its answers are kept, so "riven parmesan" is
  only looked up once:
  - **✓ Redo att laga:** everything is at home (water, salt and pepper are
    assumed; optional ingredients don't count).
  - **Saknar N:** the recipe view marks what's missing.
- **Pick what to buy:** in the recipe view every ingredient has a checkbox;
  what's missing at home is preselected. **Lägg valda i inköpslistan**
  adds exactly the ticked ones.
- **🍳 Matlagningsläge** keeps the screen on while the recipe is open
  (browser Wake Lock; needs Home Assistant opened over https).
- **Lagad** marks a recipe as cooked and has the AI subtract what it used
  from At home.
- **Cooking time:** each recipe shows its total time (⏱ 25 min), the
  time the recipe page states or else the AI's estimate. Recipes saved
  before this got an estimate once. **⚡ Max 30 min** shows only the quick
  ones, fastest first. Change the time with ✎.
- Search by recipe name or ingredient, and filter by status, time or
  category.

### Shopping list

`todo.food_planning_shopping_list` ("Inköpslista" / "Food shopping list")
is a normal to-do list: use it with the to-do card, the companion app and
Assist ("lägg till mjölk på inköpslistan").

**Duplicates are merged by the AI.** A couple of seconds after items are
added (from a recipe, by hand or by voice), the open items are sent to the
AI task, which merges items that are the same product, e.g. "2 msk
olivolja" and "15 ml olivolja" into "3 msk olivolja". Only groups of two or
more items are changed, so an item without a duplicate is never rewritten,
and an item you edited or ticked off in the meantime is left alone. Turn it
off under the integration's **Configure** button.

### At home (pantry)

`todo.food_planning_pantry` ("Hemma" / "At home") lists the food you have,
plain and simple: items moved here from the shopping list drop the recipe
names they had there. Edit it like any to-do list; ticking an item off
means it's used up.

- **Move bought items home:** `food_planning.move_bought_to_pantry` moves
  every ticked-off item from the shopping list to At home (put it on a
  dashboard button). Duplicates are then merged by the AI, as on the
  shopping list.
- **Cooking updates it:** pressing **Lagad** on a recipe sends At home and
  the recipe's ingredients to the AI, which subtracts what was used
  ("500 g pasta" → "100 g pasta") and removes what's used up. Items it
  doesn't mention, and items you changed meanwhile, are left alone. Turn
  it off under **Configure**.

### Cooking timers

Times in a recipe's steps ("koka 10 min", "25–30 minuter", "1 timme och
15 minuter", "en kvart") become ⏱ buttons. Tap one to start a timer, tap
it again to pause. Running timers show under the dashboard tabs and at the
bottom of the recipe view, with pause, +1 min and cancel. A range starts on
the shorter time.

Timers run in Home Assistant, not in the browser: every device shows the
same countdown, and closing the page or restarting Home Assistant doesn't
stop them. When one finishes, open dashboards ring and vibrate (after the
page has been touched once; browsers block sound before that), and:

- `event.food_planning_timer` ("Matlagningstimer" / "Cooking timer") fires
  `started`, `paused`, `resumed`, `finished` or `cancelled` for any timer,
  with `label`, `recipe`, `duration` and `timer_id` as attributes. One
  automation covers every timer.
- `sensor.food_planning_next_timer` ("Nästa timer" / "Next timer") is when
  the next running timer ends (unknown when none is running); its `timers`
  attribute lists all of them.

The blueprint
[`cooking_timer_finished.yaml`](blueprints/automation/food_planning/cooking_timer_finished.yaml)
sends a phone notification when a timer finishes:
[![Import blueprint](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2Fathornblom%2Fha-food-planning%2Fblob%2Fmain%2Fblueprints%2Fautomation%2Ffood_planning%2Fcooking_timer_finished.yaml)

Finished timers stay (ringing) until dismissed, at most 15 minutes.

### Actions

- `food_planning.import_recipe`: `url` **or** `text`, plus optional
  `add_to_shopping_list`. Can return the recipe as a response (`created`
  is false when the link was imported before; the saved recipe is
  returned without asking the AI again).
- `food_planning.add_recipe_to_shopping_list`: `recipe` (title or ID),
  optional `ingredients` (a subset, exact text) or `only_missing` (only
  what isn't at home).
- `food_planning.move_bought_to_pantry`: move ticked-off shopping items to
  At home.
- `food_planning.start_timer`: `duration`, optional `label` and `recipe`.
  Returns the `timer_id`.
- `food_planning.pause_timer`, `resume_timer`, `cancel_timer`: optional
  `timer` (ID or label); without it, all timers.
- `food_planning.extend_timer`: `duration` to add, optional `timer`.

## Configuration

- **AI task entity:** leave empty to use the preferred AI task entity set
  in Settings → System → General.
- **Recipe language:** the language recipes are written in (default
  `Swedish`).
- **Merge duplicate shopping items:** on by default, see above (applies to
  At home too).
- **Update At home when cooked:** on by default, see above.
- **Only administrators change recipes:** off by default. When on, only
  administrator users can edit or delete recipes; everyone can still
  import, shop and cook.
- **Recipe categories:** one per line. Removing one also takes it off the
  recipes that had it. Easier from the recipe card's **✎ Kategorier**.

All can be changed later under the integration's **Configure** button.

## Data, backups and removal

- Recipes and the shopping list are stored in
  `/config/.storage/food_planning` (timers in `food_planning.timers`), and
  recipe images in
  `/config/food_planning/images` (saved at import, since some image links,
  like TikTok's, expire). Both are separate from the code, so updates never
  touch them, and normal Home Assistant backups include them.
- Saved images are served without login at `/food_planning/images/…`,
  like files in `/config/www`. The file names are random. Image links
  (which come from the recipe page) are only fetched from public
  addresses, never from your local network, redirects included.
- Deleting the integration (Settings → Devices & services → Food Planning
  → Delete) **deletes the data and the images**. Restore a backup to get
  them back.
